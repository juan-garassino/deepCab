| Function | File | CC |

graph — **deferred** (see below).

### B.2 — `schemas/settings._maybe_read_file`

| Finding | Action | Result |
|---|---|---|
| The `file:` docker-secrets URI resolver was a top-level helper called from three identical `@field_validator(..., mode='before')` blocks (`ObsSettings.slack_webhook_url`, `OpenAISettings.api_key`, `DeepCabSettings.api_key`). Per-field validators meant every new secret field needed a new validator. | Replaced the helper + three validators with a single `FileUriEnvSettingsSource(EnvSettingsSource)` that intercepts `get_field_value` and rewrites `file:` URIs at the source layer. Wired into each affected sub-settings via a shared `_customise_sources(...)` helper called from each `settings_customise_sources` classmethod. | New surface (+30 LOC) is more idiomatic for pydantic-settings ≥ 2.4 (we have 2.14); old surface (−28 LOC) is gone. Net ~+2 LOC, but **every future secret field auto-inherits** the `file:` resolution. +2 regression tests in `tests/schemas/test_file_uri.py`. One pre-existing test updated: pydantic-settings wraps the `FileNotFoundError` in `SettingsError`, so `test_file_prefix_raises_when_missing` now asserts on the exception chain via `__cause__`. |

## Rejected findings (with reasons)

- **vulture: `deepCab/models/base.py:39 deep`** — kept because sklearn's `BaseEstimator.get_params` API contract requires the `deep` keyword by signature inspection.
- **vulture: `tests/security/.../fresh_settings`** (8 occurrences) — kept because they are pytest fixture parameters with autouse side-effects; vulture cannot model fixture injection.
- **B.3 duplicate `budget` trace writers** — kept because the inner (tool-loop) and outer (improve-loop) `BudgetExhausted` paths fire in different scopes and both must record the exhaustion event.
- **B.5 router extraction for `predict.py` / `graphql.py`** — kept because extracting helpers that have exactly one consumer adds indirection without simplifying.
- **radon CC hotspots** (`run_one_turn`, `run_improve`, `Batcher._run`) — kept because each is an inherently stateful loop (OpenAI tool-call orchestration, async batch coalescing) where splitting would push loop state into helpers without reducing call-graph complexity.
